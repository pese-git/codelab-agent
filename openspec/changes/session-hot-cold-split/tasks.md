# Расщепление горячего и холодного — Задачи

Каждый шаг: разведка → правка → тесты → `make check` + `lint-imports` → **живой прогон `--stdio`
через Zed** → разбор `~/.codelab/logs/*` → замер → коммит. Шаг не считается закрытым без живого
прогона: за прошлую сессию три вывода были опровергнуты именно измерением.

## Шаг A: горячее уезжает с носителя

> Независим от B. Закрывает остаток P2-58 и остаток P2-32. `schema_version` 8→9.

### A.1 Реестр терминалов → процессный реестр — ✅ сделано (статические гейты)

- [x] A.1.1 Разведка: поверхность оказалась узкой — состояние читают/пишут только доменные сеймы
      (`domain/session.py`), `SessionMapper`, `_drop_terminals_from_previous_process`,
      `_carry_executor_changes` и `TerminalAliasRegistry`. Context Manager (`gatherer.py`) идёт
      через ту же цепочку `tools/`, своего доступа не имеет
- [x] A.1.2 **Решение изменено разведкой: перенесена связка, но не счётчик.** Исходный замысел
      «весь реестр — состояние процесса» вводил регрессию: `terminal_counter` персистился, поэтому
      alias'ы были уникальны в сессии через рестарт, и мёртвый `term_1` давал внятное «неизвестный
      терминал». При сбросе счётчика новый процесс выдал бы `term_1` снова, и alias из
      восстановленной истории разрешился бы в **чужой живой** терминал — модель получила бы чужой
      вывод вместо ошибки. Это хуже исходного дефекта. Поэтому носители разделены: связка
      alias → client terminalId — процессная (`TerminalAliasRegistry`), счётчик — распределитель
      идентификаторов сессии и остаётся в документе, как `tool_call_counter`
- [x] A.1.3 Связка перенесена в `TerminalAliasRegistry`, адресуется `session_id`; alias'ы в
      `SessionDocument` больше не попадают. Миграция v8→v9 (`_migrate_to_v9`) отбрасывает
      `terminals`/`terminals_owner` явным `pop`, а не опорой на «лишние ключи игнорируются»
- [x] A.1.4 Удалены `terminals_owner`, `terminals`, весь модуль `process_identity.py`
      (`PROCESS_TOKEN` без вызывающих), `_drop_terminals_from_previous_process` и событие
      `terminals_dropped_from_previous_process`. Из `_carry_executor_changes` ушёл перенос связки —
      она больше не зависит от копий сессии; перенос счётчика остался
- [x] A.1.5 Ветка «неизвестный терминал» оставлена и теперь опирается на
      `TerminalAliasRegistry.known_aliases`, уровень `warning` сохранён
- [x] A.1.6 Тесты: `test_terminals_after_restart.py` переписан с поведения чистки на инвариант
      «связка на диск не попадает». Гейт персистентности — на `JsonFileStorage`, проверяет и то,
      что client terminalId отсутствует в файле целиком. Добавлены гейты изоляции сессий и
      немонотонности счётчика. `make check` — 7583 passed, `lint-imports` — 4 контракта kept
- [x] A.1.7 **Подтверждено живьём** (2026-08-05, `sess_c386dab381c8`, stdio через Zed, pid 67563 →
      70220 — рестарт на одной сессии). После рестарта модель позвала `term_4` из восстановленной
      истории и получила `terminal_alias_not_found ... known_aliases=[]` уровня `warning` — штатный
      путь. Новые терминалы получили `term_5…term_13`, на диске `terminal_counter=13`, `terminals`
      и `terminals_owner` отсутствуют, `schema_version 9`. Ноль `RPC Error -32603`, ноль `error`.

      **Прогон подтвердил именно развилку A.1.2.** Терминалов создано девять; с обнулённым
      счётчиком они получили бы `term_1…term_9`, и `term_4` из истории разрешился бы в чужой живой
      терминал — модель получила бы чужой вывод вместо ошибки. Регрессия материализовалась бы в
      этом самом прогоне.

### A.2 Ссылки на эфемерные ресурсы — проекция при сборке payload'а

- [ ] A.2.1 Разведка: где история попадает в payload модели (`HistoryBuilder`), какие ссылки на

      перезапись затирает реальные возможности подключения (остаток P2-32)
- [ ] A.3.2 Перенести на носитель подключения; из документа убрать

### A.4 Приёмка шага A

- [ ] A.4.1 Миграция 8→9: **реальный** файл версии 8 читается (не только синтетический) — v6→v7
      живьём так и не проверялась, не повторять
- [ ] A.4.2 `make check` + `lint-imports` (4 контракта kept)
- [ ] A.4.3 Живой прогон: `pipx install --force .` → `~/flutter_app` → рестарт сессии.
      Критерии: `terminals` нет в документе; обращение к alias'у прошлого процесса идёт по пути
      «неизвестный терминал», а не разрешается в чужой терминал; счётчик монотонен; ноль
      `error`/`critical`.

      **Критерий «`terminal/release` сходится с `terminal/create`» отсюда снят как ошибочный.**
      Замер 2026-08-05: 9 создано, 0 освобождено — освобождает только bootstrap Context Manager'а,
      а терминалы, созданные turn-путём по запросу модели, не освобождает никто. Это владение
      освобождением, то есть вторая половина P2-58, и к носителю реестра она не относится: после
      переноса незакрытые alias'ы больше не растят документ, но терминалы по-прежнему висят у
      клиента. Отдельный пункт, не часть шага A
- [ ] A.4.4 Обновить ADR-007 («Порядок работ» + ход реализации), tech-debt: закрыть P2-58, снять
      остаток P2-32

## Шаг B3: `history` и `events_history` — проекции журнала

- [ ] B3.1 Разведка выводимости. Измерено: `history` = 54 tool + 20 assistant + 3 user;
